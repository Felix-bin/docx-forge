## 1. 设计哲学 —— AI 主导流程，人掌控草稿

工作流对文档进行推理，逐节写作，并在明确的路线契约下编译进用户模板。确定性工具负责转换、编译、校验和预览，从不做设计或措辞决策。用户审阅方向，并在 Word 中完成最后一公里。

几个层次职责分离，不能互相替代：

| 层 | 职责 | 不负责 |
|---|---|---|
| 工作流 | 编排步骤、闸门、角色切换和交接 | Planner、Writer、检查器或编译器的决策 |
| 提示与示例 | 给出 DocMD 的规范写法和写作手艺 | 正确性或安全性 —— 它们不是边界 |
| `docmd_checker.py` | 强制执行 DocMD 契约和模板绑定；error 阻断，warning 放行 | 改写源文件或猜测意图 |
| `docmd_to_docx.py` | 把规范 DocMD 编译进模板；要求匹配的终检报告 | 修复源文件或重跑检查器 |

## 2. 为什么用流式标记语言而不是 SVG

PPT Master 用淘汰法选了 SVG：PowerPoint 是绝对定位的画布，SVG 与之世界观一致，而 HTML 的流式文档模型不一致。Word 恰好相反：Word 文档是由段落、run、列表、表格和分节组成的**流**，位置由内容和样式决定。同样的推理因此选出流式标记语言：

| 候选 | 结论 |
|---|---|
| 直接写 WordprocessingML | 太冗长、太脆弱，模型写不稳，人眼也无法审阅 |
| 自由 Markdown 或 HTML | 世界观对，但太开放：模型会写内联样式和手打编号，无法封闭和检查 |
| SVG / 绝对布局 | 世界观错 |
| **DocMD —— 受约束的 Markdown + 指令块** | 模型熟悉；人能读、能 diff；语法封闭；每个构造对应一种 Word 原生机制 |

DocMD 是项目规范语言，而不是“支持 Markdown”。作者**只写语义标签**，编译器生成所有编号和域。契约见 [`docmd-core.md`](../../skills/docx-forge/references/docmd-core.md)。

| 模型写 Word 的典型失败 | 由谁修复 |
|---|---|
| 假标题（加粗 + 放大字号） | 检查器拒绝内联格式；标题只能用 `#`，映射到模板标题样式 |
| 手打 `1.1` / `图3`，结果错号 | 编译器通过多级列表和 `SEQ` 域编号；作者写 `{#fig:x}` |
| 手写目录 | 编译器插入 `TOC` 域 |
| 术语和缩写不一致 | `doc_lock.md` 中的术语表 + 检查器警告 |
| 编造引用 | 引用键必须能解析到 `references.bib` 或素材，否则报错 |
| 长文后半段风格漂移、内容重复 | 逐节串行写作、样本章节后的早期闸门、持续更新的账本 |

## 3. 模板即模具

编译器打开模板工作区 `reference.docx` 的副本，填充声明的槽位，移除正文锚点段落，并在该处插入编译后的块。结果原样继承模板的 `styles.xml`、`numbering.xml`、主题、设置、分节属性、页眉页脚和固定区域。

**不变量 —— 不新建样式、不写直接格式**：插入的每个段落、run 和表格都引用模板 `style_map` 声明过的样式。某个 DocMD 构造的样式角色在映射中缺失时，是指向模板的检查器错误，绝不是合成格式的理由。

模板分两类（语法见 [`template_manifest_reference.md`](../../skills/docx-forge/templates/template_manifest_reference.md)）：

| 种类 | 包含 | 例子 |
|---|---|---|
| `format` | 样式、编号、页面设置、页眉页脚；正文完全由规划决定 | 公司报告格式、论文格式 |
| `document` | `format` 加上固定区域、槽位和可选的章节骨架 | 请示、项目申报书、周报 |

**先入库再使用**：用户的原始模板从不被直接消费。Create Template 先体检（假标题、手打编号、未链接的多级列表、缺少题注/表格样式、直接格式、未使用的样式），然后写出一个**新的**干净工作区，原文件从不修改。工具无法安全修复的缺陷报告为 `needs-manual`。

## 4. 产物流

```text
sources/<files> ─────────┐
analysis/source_profile ─┼─> Planner -> doc_spec.md + doc_lock.md
templates/<installed>/ ──┘
                                   │
doc_spec.md + doc_lock.md + analysis/ledger.md + assets/ + references.bib
    └─> Writer -> sections/NN_<slug>.md            （作者源）
          ├─> docmd_checker.py -> validation/quality_report.json
          └─> docmd_to_docx.py -> exports/<name>_<ts>.docx + validation/<stem>.report.json
                                  preview/current.docx + preview/blockmap.json   （实时预览）
```

`sections/` 是作者源；`preview/`、`exports/` 和 `validation/` 是派生产物。混淆这一区分，重新导出和修复就无从推理。

**长文档**：一份报告可能超出单个上下文窗口。每写完一节，Writer 向 `analysis/ledger.md` 追加内容：已定义的缩写、新引入的标签，以及用一两句话概括本节结论。下一节只读 spec、lock 和账本，从不重读前文全文。

## 5. 计划与执行的归属

| 角色 | 负责 |
|---|---|
| 用户 | 事实、素材、模板选择、期望结果、排除项 |
| Planner | 读者、目的、核心结论、文体、大纲、每节任务与证据、目标篇幅、术语表、引用格式；写出 `doc_spec.md`（人读，含理由）和 `doc_lock.md`（机读锚点） |
| Writer | 在规划的任务范围内负责行文、分段、强调，以及表格和图片的实现；只使用已准备好的素材 |
| 检查器 / 编译器 | 确定性的执行与打包 |

详细层级由 [`ownership.md`](../rules/ownership.md) 负责。

## 6. 质量闸门

**严重级别**：`error` 阻断（结构损坏、标签或引用无法解析、样式角色未映射、素材缺失、非法构造）；`warning` 放行（非规范但可安全规范化的写法、全半角标点混用、某节篇幅远离目标、术语表外的术语）。

**不自动修复**：机械补丁可能覆盖有效意图。检查器只报告；Writer 在所属层修复。

**节奏**：前一两节作为方法样本，之后过早期闸门；其余章节连续写完；终检闸门检查完整集合。编译器拒绝缺失、过期或含阻断错误的终检报告（以 `sections/` 的指纹匹配）。

## 7. 实时预览

PPT Master 预览的是作者源 SVG，因为 SVG 就是视觉真相。在 docx-forge 中，视觉结果来自模板加编译器，所以预览**必须显示编译后的文档**，同时每个块都能追溯到源文件。

| 层 | 机制 | 延迟 | 用途 |
|---|---|---|---|
| 实时 | 预览服务器监听 `sections/*.md`，去抖后重新编译 `preview/current.docx`，浏览器用 docx-preview.js 渲染 | 约 1 秒 | 边写边看，样式、页眉页脚、封面都是真实模板；分页为近似 |
| 精确 | Word COM 打开 docx，更新所有域并导出 PDF；浏览器用 pdf.js 显示 | 数秒 | 真实页数、目录页码、最终版面 |

**块映射**：每次编译写出 `preview/blockmap.json`，把正文中第 n 个块（段落或表格）映射到 `sections/<file>` 的行范围和稳定块 ID（如 `s03.b12`）。前端按顺序把点击解析到源块。这一映射将在 P1 的 spike 中验证；备选方案是给每个块加书签。

**编辑界面**：批注（需要模型处理的修改意见）存放在旁路文件 `live_preview/annotations.json` 中，记录块 ID 和引用的原文，绝不作为标记写进 Markdown。直接修改只限于措辞，以及在模板声明的样式角色之间切换某个块的样式角色；刻意不提供字体、字号、颜色控件，因为那就是直接格式。

**生命周期**沿用 PPT Master 编辑器的约定：每个项目单实例，记录在 `live_preview/lock.json`；端口从 6060 起取第一个空闲端口；闲置超时；草稿持久化，并基于摘要检测冲突；在写第一节之前以 `--live --daemon` 启动。写作期间提交的批注在导出后才应用。

## 8. 架构不变量

1. 绝不插入模板未声明的样式或直接格式。
2. 绝不原地修改用户的原始模板或源文档。
3. 所有编号、题注、交叉引用和目录都由 Word 机制生成，绝不手打。
4. 保持素材、作者源、派生产物和交付产物可区分。
5. 修改任何产物之前，先选定路线及其变更契约。
6. 构造无法安全表示时，失败即停止（fail closed）。
7. 章节由主 Agent 逐节手写；绝不用脚本批量生成正文。
