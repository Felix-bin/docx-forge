# 项目定位与能力边界

[English](../project-positioning.md) | [中文](./project-positioning.md)

---

本文定义 docx-forge 的长期产品定位，以及新增、保留或移除能力的判断标准。它是产品政策，不是功能清单或执行手册。英文版为准，本文为同步翻译，须在同一次变更中更新。

## 1. 定位

> **docx-forge 是一个对话驱动的工作流：先让 AI 把文档的论证理顺，再写作，并编译进用户自己的 Word 模板，产出真正原生样式化、可编辑的文档，而不是粘贴文本加手工格式。它的核心轴线是“模板保真 + 原生深度”：每个段落都使用模板样式，每个编号都由 Word 生成，每个引用都是活的域。**

形式上，docx-forge 是运行在具备 Agent 能力的 AI 工具中的 skill。工作流提供文档推理、契约和质量闸门；确定性工具负责转换、编译、校验和预览；所选模型仍决定质量上限。

主要交付物是用户可以继续打磨的高质量 Word 草稿，而不是封死的终稿。

## 2. 产品主张

| 轴线 | 立场 | 结果 |
|---|---|---|
| 逻辑优先 | 动笔前先确定读者、目的、核心结论、文体和章节骨架 | 结构是推理出来的，而不是照搬素材顺序 |
| 模板即模具 | 用户模板拥有样式、编号、页面设置、页眉页脚和固定区域 | 编译器从不新建样式或写直接格式；缺样式是模板问题，不在正文里打补丁 |
| 原生深度 | 标题是绑定多级列表的样式；题注是 `SEQ` 域；交叉引用是 `REF` 域；目录是 `TOC` 域；注释是真正的脚注 | 文档在 Word 中继续编辑不会坏：重新编号、改样式、更新域都正常 |
| 诚实的可编辑性 | 产物是草稿；预览保真度和分页限制明确说明，不隐藏 | 实时预览是近似的；精确分页来自 Word 本身 |
| 用户掌控 | 模板、项目状态和产物都留在本地、可检查 | 没有托管服务、点数，也不绑定某个 Agent 或模型 |

## 3. 目标用户

需要在既有机构模板下产出结构化 Word 文档（报告、公文、方案、论文、SOP）的人；在意结果样式正确、可编辑；愿意审阅方向并在 Word 里完成最后一公里。

不针对：零配置浏览器生成、自由版式排版、实时协同编辑。

## 4. 产品承诺

| 承诺 | 含义 | 边界 |
|---|---|---|
| 模板保真 | 产物只使用所选模板的样式、编号、页面设置和固定区域 | 模板缺陷在入库时报告，绝不用直接格式悄悄补上 |
| 先逻辑后行文 | 写作前规划大纲、证据和每节任务 | 保留类请求（填充或修订）保持原文措辞和顺序 |
| 素材保真 | 事实和引用可追溯到素材或参考文献库 | 不编造引用；无依据的说法要标出，而不是抹平 |
| 工程可靠 | 明确路线、阻断式检查器、带指纹的报告、可恢复的项目状态 | 不做静默降级；必需闸门失败即停止导出 |
| 数据本地 | 转换、编译、预览和导出都在用户机器上运行 | AI 模型和用户选择的服务仍会收到调用所需的输入 |

## 5. 能力模型

| 领域 | 职责 |
|---|---|
| 文档推理 | 把主题或素材包变成面向读者的目的、文体、大纲和章节计划 |
| 模板入库 | 体检用户的 `.docx` / `.dotx`，报告缺陷，提炼出干净可复用的模板工作区 |
| 原生文档创作 | 编写 DocMD 章节，并编译进模板成为原生 Word 结构 |
| 既有文档改编 | 在保留契约下填充、修订或批注已有文档 |
| 审阅与交付 | 实时预览、精确预览、批注、校验、导出和回读 |

## 6. 非目标

docx-forge 不打算成为：

- 通用 DOCX 转换器或任意 OOXML 编辑器。
- 桌面排版或绝对定位版式工具。
- 替机构发明格式的模板设计器；它只消费并清理用户提供的模板。
- 承诺一次生成完美终稿的系统。
- 原地升级用户原始模板文件的工具。

## 7. 能力准入测试

按顺序评估每个拟议能力：

1. **用户任务** —— 它完成什么真实的文档任务？
2. **核心贡献** —— 它是否加深模板保真或原生结构、改进文档推理、增强用户掌控，或让交付更可靠？
3. **产出归属** —— 它创建或保护什么产物、决策或质量属性？
4. **不变量** —— 什么必须保持不变？
5. **可验证** —— 能否不靠模糊说法检验成功与失败？
6. **证据** —— 背后是否有真实的重复需求或已发生的失败？

提示文件中的每条新规则都应能追溯到一次已发生的失败；为预防而预写的规则是待删候选。
